# 全体系Contentバランス調整原則

## 1. 目的と評価単位

初期の研究・産業基盤から太陽系規模の活動へ連続して発展するゲームを、研究・資本取得・継続産業・物流・立地・人口・時間が結合した**一つの発展構造**として調整する。LLMは技術体系、活動、規模、期間、構成と採否を設計する。CLIはGameApplicationの正準係数・実Stateと明示された仮説から数量・依存関係を示すのであって、最適戦略やContent適正値を算定しない。

研究の表示段階と累計プレイ時間は変更可能な全期間の観測枠であり、CoreのGateでも全研究の必修期限でもない。各期の全研究取得、特定の資産数、特定地点や唯一の攻略順を暗黙に要求しない。発展目的・内容・規模・時期自体を再設計できる。

## 2. 発展目的と結合制約

研究・宇宙活動の工学的役割、取得する能力、産業・物流・居住の地域的分担、期間、世代間継承、複数の成立方法を全期間の発展目的として明示する。活動・Technology・Facility・Vehicle・Process・Resource・World・Service・取得条件を実DefinitionとApplication契約へ接続する。未選択の方式と未記述の活動を、ゼロ需要や完了済みの条件と混同しない。

取得投資・継続運用・Research Stage・Power・Work・Service・Inventory・Fleet・輸送・人口の数量を、期間、地点、共有Resource、有限能力と資産の関係で同時に扱う。複数の出力・副産物を持つ工程は一度の稼働として計上し、前後期間の共用設備と取得負担を接続する。初期Stockと生産Flow、名目能力と実Allocation、設計上の資産取得と実取得State、輸送の出発需要と到着未確認を区別する。供給選択、技術解禁、地質・Site、Research実行、輸送往復・遅延、循環する資産取得条件は未確認のまま保持する。

全体系KPIは発展目的に対する研究世代と産業投資、産業と物流・立地、人口と継続供給、世代更新と時間配分の**相互整合性**である。個別の不足量、数量増加、部門別スコア、単一総合点、形式的な段階網羅を採否基準にしない。判断用の粗い結合関係と追跡用の係数・Definition根拠は同一のモデルから生成する。未成立と未選択を意味上の妥当性認定へ変換しない。

## 3. LLMによる調整の6工程

1. **全期間の発展目的を構成する。** 研究・産業・物流・居住・時間の活動像と規模、技術的役割、前後期の継承、代替方法を仮説として置く。
2. **発展目的を結合制約へ接続する。** 正準ApplicationのRequirement・数量係数・開始実Stateを参照し、取得・運用・供給・能力・物流・時間を同一の関係へ接続する。
3. **全体系の相互整合性とトレードオフを判断する。** 論点・詳細参照を絞っても、別期間・別地点・共通Resource・代替方法への影響を辿る。
4. **発展構造に基づいてContentへ変更を反映する。** Research・Facility・Vehicle・Process・Resource・World・初期条件・活動規模・期間を一体で調整する。
5. **同一の全体系で採否を判断する。** 変更後の全期間の発展内容、成立条件、競合、前後世代への負担転嫁と未確定要因を確認する。
6. **実成立性を必要に応じGameApplicationで検証する。** 通常Command・Query・状態遷移による確認結果を全体系の判断に戻す。

各サイクルの採否単位は常に全期間とする。実装単位や技術的詳細参照の細分化は採否単位の縮小を許さない。数学的な大域最適解の証明は要求しないが、根拠不足は調整未了として扱う。

## 4. 入力と評価

公開操作は `python -m space_idle.dev_cli --targets <path> [--from-save <path>] [--output <path>]` の一つ。入力 `space-idle.development-structure.v2` は全体意図と相互に関係する発展目的、累計時間順の期間、目的に紐づくResearch・資産取得・工程・輸送・人口活動からなる。選ばなかった供給方式や取得順をCLIが自動補完しない。技術的根拠には参照した期間・地点・Definition・数量・出典・条件を保持する。結合関係は同じ数量・依存台帳から構築し、独立の局所評価経路を作らない。

評価器は既存の設計を根拠のない自動計画へ変換しない。検証は、計算・責務契約とLLMによる全期間の実際のContent選定・調整・採否を分離して行う。表示が埋まったこと、局所数量が改善したこと、テストやpublishが成功したことだけを全体バランス調整の完了としない。
