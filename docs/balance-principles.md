# 研究・産業・物流の全体系バランス調整原則

## 1. 目的と位置づけ

本書は、現代地球の宇宙開発組織から太陽系規模の産業圏へ至るゲームについて、**研究8表示段階に対応した発展仮説を設け、研究・産業・物流・拠点・人口の数量と時間を一体で調整する実務原則**を定める。調整の目的はPlayerの最適攻略を求めることではなく、技術・設備・立地・供給網の発展が工学的に説明でき、Idleゲームとして世代交代と物量拡大を伴って成立するContentを設計することである。

ゲーム上の意味と研究・産業・物流の規則は `design.md` §5–16・§20・§22、State ownership・物理係数・評価基盤の境界は `architecture.md` §5–12・§17.1、開発と検証の手順は `development-principles.md` を正本とする。本書はそれらを上書きせず、全8段階の研究・産業・物流ロードマップの活動像を、Content調整で実際に使う判断・評価単位へ統合する。研究定義、各Content Definition、World、初期Scenarioの具体値はそれぞれの所有Definitionを唯一の参照元とする。

表示段階・分野・技術系列は研究を理解するためのmetadataであり、Coreの進行ゲートではない。段階末に全研究を終えること、特定天体へ進出すること、特定数のFacility・Vehicle・人口を保有することをゲーム内の必達条件にしない。段階別プランも仕様上のBuild順や推奨攻略手順ではなく、**Contentと発展像そのものを見直せる設計仮説**である。

## 2. 評価の起点と時間尺度

ゲーム全体の中心ループは、有限の研究資産・科学活動からResearch Point (RP) とKnowledgeを得て技術を獲得し、産業・輸送・研究の実手段を建設・運用し、さらに大規模な研究と域外活動へ進むことである。研究の高度化に伴うRP需要、RP/day、Research execution、Pool容量の増大だけでなく、それを支える採掘、Process、Construction、Fleet、Power、Maintenance、Life Support、輸送時間、World条件を同じ設計問題として扱う。

1 game day = 実時間1秒を基準速度の時間換算とする。全8段階の累計実時間 **4 / 12 / 28 / 60 / 124 / 220 / 364 / 580時間**は、到達可能な活動規模を評価するための暫定的なペーシング基準であり、各段階の全研究取得期限ではない。区間時間は順に **4 / 8 / 16 / 32 / 64 / 96 / 144 / 216時間**であり、前段階の累積投資を無視して各区間を独立に満たすものではない。580時間そのものや段階の区切りも、全体評価によって再検討できる。

ロードマップで整理した研究695件・19上位分野・32技術系列、およびFacility・Process・Vehicle・Resource・Worldの構成は、体系の規模と連接を検討するための設計時点の目録である。件数、段階別の件数、Theory RP総額を分配ノルマやCore契約にせず、研究DefinitionとContentの変更後に必要な値を再集計する。全研究のTheory RP合計を経過時間で割っても、取得する研究の枝、typed Stageの実行、設備建設、能力の増強、RP Poolへのadmission、複数活動の競合を説明できない。

## 3. 全8段階の発展仮説

各行は「その頃に検討する主な活動・規模」と「量的調整の焦点」である。前後段階の活動は並行・重複し得る。研究枝と活動の成立は、それぞれの実Definitionと物理的要件で判断する。

| 表示段階と累計目標 | 研究・宇宙活動の発展像 | 産業・物流・規模の評価焦点 |
|---|---|---|
| **1 軌道活動・近傍天体探査／4時間** | 航法、打上げ、遠隔操作、観測、基礎電力・熱と軌道研究。月面無人作業への進出を検討 | 地球の有限Source→基礎加工→研究・施設建設・Vehicle製造、初期打上げ、Cargo、最初の域外Founding |
| **2 長期無人域外活動／12時間** | 長期無人運用を主軸に与圧・生命維持・着陸等の有人技術も発展。月面複数有人拠点の成立可能性と火星無人探査・準備を検討 | Fleet更新・増産、居住・Crew Service・旅客輸送の取得負担、遠隔拠点の継続補給と並行研究 |
| **3 長期有人域外活動／28時間** | 火星等への長距離有人活動、遮蔽・医療・閉鎖環境、現地水利用、地表研究 | 複数有人拠点の維持需要、長距離旅客・貨物のFleet競合、輸送遅延と研究・製造能力の拡張 |
| **4 恒久的域外活動／60時間** | 小天体・惑星近傍への探査拡張、Survey、建設・保守・補給・試験的現地加工の反復 | 試験設備と量産設備の役割差、複数候補立地、建設・保守の反復負担、拠点間物流 |
| **5 域外産業化／124時間** | 現地採掘、選鉱・精錬、部品加工、長期産業運用への転換 | Extraction→Process→Consumerの物量、Power・排熱・Maintenance、工場増設、現地生産と輸入の競合 |
| **6 惑星間産業ネットワーク／220時間** | 地球外拠点間の分業、分散製造・研究・自律運転。高度輸送・人工重力等の基礎 | 幹線・支線Fleet、共有中間材、長距離輸送の遅延・折返し、各拠点の自立度、交換部品・継続供給 |
| **7 外惑星・極端環境活動／364時間** | 低日射・極低温・高放射線等の環境、核融合・高出力光学・合成生態系等の技術課題 | 遠隔補給、長期保守、極端環境設備の電力・熱・材料・燃料循環、新方式の物理的取得・維持負担 |
| **8 太陽系規模インフラ／580時間** | 分散産業、資材循環、長寿命無人機、長期通信・観測、初期星間探査を構想できる基盤 | 広域幹線物流、施設更新・資材再循環、大規模居住・研究、ビーム帆・運動量交換等の有限インフラ |

第1段階から無市場で地球産業を持続させ、第2–3段階では有人活動の必要Resourceと旅客移送を明示し、第4段階の試験的利用と第5段階の量産を混同しない。第6段階以降は設備の種類が増えただけで成長とみなさず、施設数量、Fleet配分、日次物量、交換部品、維持の規模がどのように増すかを評価する。第7–8段階のSF方式も実Facility・Vehicle・Process・Operationの有限能力として実装可能かを確かめ、研究完了だけで現物・能力・航路が出現すると仮定しない。第9段階以降の追加可能性を妨げない。

## 4. 段階別評価プランの構成

各段階のプランには、同じ観点から次を記述する。初期値や施設台数を固定する様式ではなく、比較と調整に必要な根拠を記録する単位とする。

1. **活動・到達像**：どのような科学活動、研究設備、継続産業、物流網、居住・拠点機能を、どの程度の物量で成立させたいか。その規模を選ぶ工学的・ゲーム的理由と、他段階との関係。
2. **研究の成立経路**：その活動に関係するTechnologyとdirect prerequisite、Theory・Prototype・Demonstration・Operational Experienceのtyped Stage、必要な実行場所・試作材・Knowledge。別枝・別方式による実現可能性も検討する。表示段階の全研究を取得済みとしない。
3. **研究供給と並行需要**：採用した研究群と並行する研究群のRP要求、RP/day、Research execution、Pool容量、必要Provider・Facility・Fleet・Power・Maintenance。初期解禁は実Scenarioのcompleted technologiesを参照する。
4. **産業・資産の規模**：各地域の採掘、加工、電力、建設、研究、製造、保守、居住のFacility種類と数量を仮定し、その取得Resource・work、稼働Service、継続資材、増設負担を集計する。Facility Levelは設置台数、Provider Tierは研究手段の世代であり、段階から性能を推定しない。
5. **物流・立地・人口**：WorldのEnvironment・Terrain・Resource PotentialとSurvey Knowledge、拠点Founding、Fleet用途・積載・航行・折返し、必要な輸送方向・頻度、Cargo遅延、Crew・旅客移送、Housing・Life Support・食料・水・酸素の継続需要。複数立地・調達構成の余地を残す。
6. **前後段階との資産接続**：前段階の稼働資産・維持負担、途中の設備取得・増設・更新、次世代研究手段や産業に必要な先行投資、後期まで残る旧世代設備の役割。
7. **数量・時間・改訂判断**：期間と地点を明記した需給・capacity・所要時間の根拠、観察されたlimiting factor、想定規模自体を変更する理由、Content変更候補と隣接段階への波及。

個別プランは同じゲーム全体の発展像を別の成熟度から観測したものであり、8件の独立Scenario、段階開始時に完成済み資産を与えるfixture、順番どおりに再生するPlayer Scriptではない。複数の成立方法がある論点では、その違いが研究・投資・供給網へ与える影響を吟味するが、あらゆるBuild候補の網羅や最適解探索は行わない。

## 5. 全体系の需給と時間を同時に評価する

### 5.1 取得と継続稼働を分け、同時需要として結合する

各地点・Resource・期間について、有限Source、Extraction、Process出力、搬入と既存在庫を供給側として、研究試作、Construction、Vehicle Production、Industry投入、Maintenance、推進剤、居住・探査、搬出を需要側として扱う。中間製品を上流・下流で二重計上せず、投入と産出、消費場所と生産場所、初期Stockと継続生産を区別する。建設・Fleet取得の**一時的な資本負担**と、建設後に毎日発生する**継続運用負担**を別に算出して、同じ期間の競合として再結合する。

Power、Research execution、Construction work、各Service Capacity、Inventory admission・荷役、Fleet commitment、RP Pool admissionも有限の共通制約である。能力の名目値から実稼働率、Cargo到着、Technology取得、Resource供給を自動成立させない。研究・建設・製造・輸送を順番に単独評価した結果を足して「同時に成立」と判定しない。逆に、同時並行できる活動をすべて直列に扱って過大な期間を見積もらない。

### 5.2 RP・研究Stage・世代更新

研究コストの検討対象はTheory RPだけではない。Prototypeの試作材とExecution Site、Demonstrationのwork・継続Service、Operational Experienceの実活動由来Knowledge、直接前提研究、並行ProjectのAllocationを含む。RP生成とResearch executionは別の有限能力であり、Providerの取得・配置・運転、Archive等のPool投資、RPのadmission余力と各活動の競合を考える。Scientific ExplorationはFleetを輸送等と競合させる有限の研究・Knowledge獲得手段であり、無制限RP源にしない。

研究Providerの世代交代については、旧Tier設備の増設継続と新Tierへの投資の双方に成立余地があり、大規模化した時の効率差が自然に生まれるかを調べる。表示段階の更新だけで設備を自動改造しない。各研究の直接前提と実際に使うContentのTechnology eligibilityを辿り、表示分類やseries内の順序だけから解禁を推論しない。研究分類・技術系列の横方向の密度と縦の成熟、研究と実Contentの接続不足も一体で再検討する。

### 5.3 物流・World・人口

輸送は片道payloadだけではなく、往復または再配置までの車両拘束、推進剤・整備、出発元と到着先のインフラ、Station能力、Cargo handoff、供給頻度と航行遅延を含める。需要を満たす名目Fleet数量と、Fleetが実際にcommitされ輸送されることを分ける。初期拠点成立はKnowledge・Site Eligibility・Founding Deployment Recipe・Cargo到着などの実要件に従う。地球・月等を特別なCore例外として扱わない。

複数天体・Surface CellのEnvironment、Terrain、Resource Potential、採掘機会と距離の違いを考慮し、特定地点を唯一の正解にしない。Surveyは情報を公開するのであって潜在資源そのものを増加させない。現地生産への転換は搬入量の減少だけでなく、必要な研究・新設備・電力・維持・加工の負担と比較する。

人口は旅客の実到着と拠点別の自然増加により変わり、Housing、Life Support、有限ResourceとPowerに拘束される。人口を生産力・有人活動の条件としても継続維持対象としても扱い、輸送中の人数を居住人口に二重計上しない。拠点別の自然増加停止を尊重し、段階別の人口ノルマや人口だけで決まる自動拡張を導入しない。大規模居住・研究・産業化が進むほど、設備種類の追加だけでなく人員当たりの処理能力や施設規模がどう変わるかを調べる。

### 5.4 長期時間と遅延・継続性

時間目標はRP総額÷単一時点のRP/dayで検証しない。初期Scenarioから必要資産を取得するまでの準備期間、RP・生産・建設能力の段階的増設、輸送遅延、Fleet拘束、Research Stage、同時操業需要を含めて妥当性を判断する。累計580時間の目標に対し、前半の設備投資と後半の大規模自動運用がどの程度の期間を占めるかを確認する。速度変更・Offline進行のDomain契約を調整用計算で置き換えず、実ゲームの時間進行の成立性は別途検証する。

## 6. Contentの接続と変更対象

初期の無市場成立では、有限の鉱物・水・炭素・栄養塩等のSourceから、構造材、機械、電子・精密部品、酸素・推進剤、食料まで必要な工程が接続され、研究・施設建設・Vehicle製造・人口維持の需要が競合しても持続できることを目指す。初期在庫による一時的な運転や市場取引で、生産連鎖の欠落・恒久的な供給不足を埋め合わせない。

構想表にIDがあることと、ゲーム内に登録されたResource・Facility・Vehicle・Process・Provider・Campaign等のDefinitionが存在することは異なる。未登録または能力未定義の構想は需給上の実在供給に算入せず、必要な場合は具体的な物理Contentの設計・登録を先に行う。登録済みでも Technology prerequisite、Capability、Construction/Production/Maintenance、Power・Service、Movement、Application・Persistence・Offlineまで機能上つながらなければ、成立した資産とみなさない。

SF技術は新しい研究名だけを評価しない。運動量交換・電磁射出は運動量と軌道回復のコスト、ビーム給電・帆は送信Power・放熱・指向・設備、核融合は燃料・磁場・炉壁・冷却、人工重力は構造と運用、合成生態系は物質入出力と維持を要する。新方式の利点と取得・運用負担を同一の有限体系に置き、無限Service・無償Resource・自動到達能力を導入しない。

研究・Facility・Process・Vehicle・Resource・World・Scenarioの分類、種類、役割、性能、投入量、資源分布、初期資産はすべて調整対象である。既存項目を所与として倍率だけ合わせず、工学的に不足した工程や不自然な重複があればContentの追加・改廃と数値調整を組み合わせる。後期施設は単なる名称や一律倍率ではなく、規模・環境適応・資源変換・自律化等の技術的理由に基づいて設計する。

## 7. 調整の実施順序と証拠

1. **全段階の活動像を一括点検する。** 前後の技術系列、研究手段の移行、産業・物流の量的成長を見渡し、早期段階への機能集中、後期の内容希薄化、不合理な断絶を先に直す。
2. **登録Contentと設計構想を照合する。** Technology DAG、各Research Stage、Definition、World、初期Scenarioの接続を調べ、未登録・未確定を区別する。目録上の存在だけで物理的な供給能力を宣言しない。
3. **段階ごとの投資・稼働仮説を作る。** 初期から累積するAsset取得、稼働する旧世代・新世代設備、Research、施設・Fleet建造、物流、人口維持を同時に置き、設計者が想定した活動量の妥当性も問い直す。
4. **必要な数量を同一単位・期間・地点で照合する。** 登録DefinitionとDomainの副作用のない係数を参照し、需給の競合、capacity、遅延、取得投資、時間の制約を区別する。未知の量を任意のTBC値で補わない。
5. **設計変更をContentのまとまりとして行う。** 単一FacilityやRP値の調整で閉じず、供給元、加工、Consumer、Vehicle、研究手段、Worldと次の段階への影響を確認する。必要なら段階プラン自体を改める。
6. **変更後に全体系と隣接段階を再評価する。** 対象段階だけでなく前段階からの投資と後段階に残る維持負担を確認する。複数の合理的な成立方法を妨げていないかも調べる。

評価結果は、**段階の活動像、検討した規模、採用・変更するContentと理由、期間付き需給・時間の主要根拠、未確定の物理条件、前後段階への影響**を残す。出力項目や比較プラン数そのものは成果ではない。判定できない理由が計測契約の欠落なら所有Domainの係数取得を調べ、単に必要性の薄い詳細分析なら実施しない。研究・設備・Worldの内容や数量が未確定なら、成立を断言せず先に内容を設計する。

## 8. 分析手段・Gameplay検証と完了判断

設計用の数量読取は `content_balance/` と `scripts/content_system_review.py` 等の開発専用経路で行い、第1・第2段階等の評価シナリオは `balance_evaluation/` の明示実行で条件付き数量を出力する。これらはバランス保証用のテストではない。数量の算出には研究・設備・輸送等の実Definitionと所有Domainの副作用のない物理係数を使う。目的が明確な目録、関係の読取、期間・Node指定の需給表を優先する。完全な仮想Player State、独立の日次Simulation、全プランの自動再生、最適化スコア、警告網羅器をバランス調整基盤に追加しない。

実行可否、Resource保存、Allocation、Fleet commitment、Technology eligibility、Save/Load、Offline、Application Query等の機能契約は実Domain / Applicationで必要範囲を検証する。Content評価とCore機能テストは別の証拠とし、段階プランの台数・日数・拠点・研究順を恒久テストの正解として固定しない。評価ツールの内部的な計算・参照契約の確認は、段階別評価の合否とは切り離し、通常テスト・Fast CIから分離する。

調整の進展は、次の観点で判断する。

- 8段階を通じて、研究・産業・物流・居住・World条件の**構成と量的成長**に説明可能な連続性があるか。
- 初期Scenarioから無市場で投資と継続運用を成立させる筋道があり、後期の大規模化にも前段階からの取得・維持負担が接続しているか。
- RP供給、実行、貯蔵、typed Stage、設備更新と、産業・物流・人口の競合が共通の時間尺度で評価されているか。
- 不足・過剰・重複・断絶の根拠からContent・プラン双方を見直し、関連する段階で再評価したか。
